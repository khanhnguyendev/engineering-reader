# M6: Pipeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The pipeline runs on a schedule in shadow mode, and `pnpm shadow-status` reports whether the shadow-mode exit condition holds.

**Architecture:**
- **Shadow status.** `lib/pipeline/shadow-status.ts` is a pure function over the list of pipeline PRs; `scripts/shadow-status.ts` fetches them with `gh pr list` and prints the verdict.
- **Routine.** A Claude Code scheduled cloud routine (controller-created with RemoteTrigger) runs `docs/pipeline-prompt.md` verbatim against this repo. The controller runs it once by hand, reads the run log, and fixes the contract docs if the run trips.

**Tech Stack:** unchanged. No new dependency.

**Spec:** `docs/superpowers/specs/2026-10-21-engineering-reader-design.md` §9 (shadow mode, clean definition, shadow-status), §10 (M6).

## Global Constraints

- Exit condition: 5 consecutive `clean` merges and at least 21 days since the first pipeline PR (spec §9: "5 consecutive clean PRs and no earlier than 3 weeks").
- Clean = merged PR carrying the label `clean` (Ryan applies it). A merged pipeline PR without `clean` resets the count to zero.
- PRs from `pipeline/dry-run-*` branches never count, never reset, and do not start the clock.
- Ruling: ledger-only PRs (`pipeline/ledger-*`) carry no post, so they neither count toward nor reset the streak; they do start the clock.
- Unmerged (closed or open) PRs neither count nor reset.

## Review Focus

1. No pipeline PRs at all: report 0 clean, 0 days, not met, without crashing.
2. Merged-but-not-clean PR in the middle of a run of clean ones: the streak counts only the clean merges after it.
3. Dry-run PRs (there is one, #7, already closed) must not start the clock.
4. `gh` missing or unauthenticated: exit 1 with gh's stderr, not a stack trace.
5. Day count uses whole UTC days between the first PR's `createdAt` and today.

### Task 1: shadow-status

**Files:**
- Create: `lib/pipeline/shadow-status.ts`, `scripts/shadow-status.ts`; `package.json` script `"shadow-status": "tsx scripts/shadow-status.ts"`
- Test: `tests/pipeline/shadow-status.test.ts`

**Interfaces:**
- `type PipelinePr = { number: number; headRefName: string; createdAt: string; mergedAt: string | null; labels: string[] }`
- `type ShadowStatus = { consecutiveClean: number; days: number; firstPr: number | null; exitMet: boolean }`
- `shadowStatus(prs: PipelinePr[], today: string /* YYYY-MM-DD */): ShadowStatus`
  - drop `pipeline/dry-run-*`; `firstPr`/`days` from the earliest `createdAt` of the rest (`days = floor((Date.UTC(today) - Date.parse(createdAt)) / 86_400_000)`, 0 when none);
  - streak: merged PRs not on `pipeline/ledger-*`, sorted by `mergedAt` descending, counted while `labels` includes `clean`;
  - `exitMet = consecutiveClean >= 5 && days >= 21`.
- `formatShadowStatus(s: ShadowStatus): string` — three lines: `Consecutive clean merges: N (need 5)`, `Days since first pipeline PR: N (#M) (need 21)` or `Days since first pipeline PR: — (no pipeline PRs yet)`, `Exit condition: met` / `Exit condition: not met`.
- CLI: `gh pr list --label pipeline --state all --limit 500 --json number,headRefName,createdAt,mergedAt,labels`, map `labels[].name`, print `formatShadowStatus(shadowStatus(prs, today))` (today = UTC date). Exit 0. If `gh` fails, print its stderr and exit 1.
