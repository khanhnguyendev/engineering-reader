# M8a: Pipeline Contract v1.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the contract gaps the first real pipeline run (PR #10) reported, so good items over the per-run cap are not lost, diagram labels cannot trip the reference check, and normalizing 100+ links is fast.

**Architecture:** One new ledger decision (`deferred`), a validator fix (references are not scanned inside fenced code), a batch mode for `normalize-url`, and contract doc updates.

**Tech Stack:** unchanged.

**Spec:** `docs/superpowers/specs/2026-10-21-engineering-reader-design.md` §5 (seen.json, validation), §9; `docs/pipeline.md`.

## Global Constraints

- `deferred` = met the selection bar but over this run's cap. It needs `reason`. A later run re-decides a deferred item: it is the only entry a run may rewrite, and only to `picked` or `skipped`.
- Cap wording everywhere: "at most three picks per run".
- Reference rule: `[S<n>…]` references count only outside fenced code blocks (``` … ```), in every locale.
- `pnpm -s normalize-url` keeps its one-URL behaviour; with several arguments, or with `-` (stdin, one URL per line), it prints one normalized URL per line in input order; an invalid line prints `ERROR <input>` on stdout for that line and the exit code is 1 at the end.

## Review Focus

1. A body that cites `[S1]` only inside a mermaid label must now fail "source S1 is never referenced" if it is cited nowhere else.
2. A `deferred` entry without reason fails validation; with `slug` fails (deferred has no post).
3. `ledgerCounts` reports deferred separately; the PR body ledger line includes it.
4. A run rewriting a `deferred` entry to `picked` must not be flagged by any check as "rewrote an entry" (no such check exists; doc must say it is allowed).
5. Batch normalize with a blank line: skipped silently.
