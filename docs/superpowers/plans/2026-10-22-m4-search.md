# M4: Search Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **Superseded in part (2026-10-26, commit f5f73b3):** Task 1's indexing mechanism (postbuild CLI crawl of `.next/server/app`, `data-pagefind-*` markup, folded attribute) was replaced by a content-based index built in `prebuild` with Pagefind's Node API, because Vercel's builder has no prerendered HTML in `.next/server/app`. See spec §8 "Recorded (M4)" and `docs/decisions.md`.

**Goal:** Visitors can search posts from `/[locale]/search` in both locales, and accented and unaccented Vietnamese queries ("dữ liệu" and "du lieu") find the same post.

**Architecture:**
- **Indexing.** Pagefind indexes the prerendered post HTML in `.next/server/app` after `next build`. It splits indexes per language from `<html lang>` and writes them to `public/pagefind/`. Only post pages are indexed: their `<article>` carries `data-pagefind-body`, and Pagefind skips every page without it once any page has it.
- **Matching unaccented queries.** Each post page carries an accent-folded copy of its title, summary, TL;DR and body. It is an attribute value indexed through `data-pagefind-index-attrs`, so "du lieu" matches.
- **Display.** Pagefind appends index-attrs text inline with page content, so its excerpts can contain folded text. The UI therefore never renders Pagefind excerpts. Each result row shows the post's own title, summary and company, taken from `data-pagefind-meta`, which holds the accented originals.
- **Search page.** `/[locale]/search` is static. A small client component lazy-loads `/pagefind/pagefind.js` and renders rows with the site's own tokens.

**Tech Stack:**
- Next.js 16.4.2, unchanged.
- **pagefind 1.5.2**: MIT, a devDependency, and the only new dependency (named by spec §8).
- vitest + jsdom for tests.
- puppeteer, already a devDependency, for the built-index checks.

**Spec:** `docs/superpowers/specs/2026-10-21-engineering-reader-design.md`:
- §6 IA: `/[locale]/search` is the Pagefind UI.
- §8 Search: "Pagefind runs post-build over the static output, one index per locale …; the search page loads the Pagefind UI lazily and matches the world. Both accented and unaccented Vietnamese queries must match … index an accent-folded copy of title, summary and body alongside the original … Builder's call, recorded here."
- §8 Rejected: other client-side search libraries.
- §10 M4: done when a Vietnamese diacritic query returns the right post.

DESIGN.md is the visual authority for the search page.

## Global Constraints

- No runtime file reads. The index is static files under `/pagefind/`, produced by the `postbuild` script (`pagefind --site .next/server/app --output-path public/pagefind`). `public/pagefind/` is gitignored.
- One index per locale, split by `<html lang>`, which the locale layout already sets. A vi query never returns en posts, and an en query never returns vi posts.
- Only post pages are indexed. `data-pagefind-body` goes on the post `<article>`. Sources, Related, SeriesNav, TOC, share and byline rails, and the JSON-LD script inside the article carry `data-pagefind-ignore`.
- Folding: `fold(s) = s.normalize('NFD').replace(/\p{M}/gu, '').replace(/đ/g, 'd').replace(/Đ/g, 'D')`. Folded text is never rendered to users, never visible, and never exposed to assistive tech.
- Pagefind result URLs have the shape `/<locale>/posts/<slug>.html`. The site path is that URL with `.html` removed. `toSitePath(url)` does this, and Task 1 verifies the shape against the real index.
- The search page uses the "Pagefind UI" through Pagefind's JS API, not its default UI widget. That is how it "matches the world": DESIGN.md tokens, hairline list rows, no new border role, both themes, phone first, `<main id="content">` and `PageIntro`.
- All copy comes from the dictionaries, with key parity and no hard-coded English on vi.
- `buildMetadata` is used for the search page. Search pages are `noindex, follow`, are left out of the sitemap, and are linked from the header nav.
- Commit messages end with the session's two attribution lines.

## Review Focus

1. "du lieu" and "dữ liệu" on vi both return the Discord post and nothing from en. Covered by the Task 1 index check and the Task 4 UI check.
2. An en query returns only en posts, and a Vietnamese query on en returns nothing. Covered by Task 1 and Task 4.
3. No folded text reaches the screen. Result rows show the accented meta title and summary, never the excerpt. The post page has no visible or accessible folded text. Covered by Task 1 (markup), Task 2 (rows render meta, not excerpt) and Task 4 (row text contains an accented character for the vi results).
4. If the index is missing (`next dev`) or fails to load, the page shows a localized "unavailable" or "error" state. It must not crash or spin forever. Covered by Task 2.
5. An empty query shows nothing, and a no-match query shows the localized "no posts match" line. Covered by Task 2 and Task 4 (a zero-results negative control).

**Interfaces (Produces):**
- `fold(s: string): string` uses the formula above.
- `plainText(md: string): string` drops fenced code blocks and URLs, and strips the characters ``# * _ ` > [ ] ( ) |``.
- `toSitePath(url: string): string` removes a trailing `.html`, so `/vi/posts/x.html` becomes `/vi/posts/x`.
- Post page markup:
  - `<article data-pagefind-body …>` with `data-pagefind-ignore` on the excluded blocks.
  - `data-pagefind-meta` on the article: `title:<title>, summary:<summary>, company:<company name>`. Values are escaped by Pagefind's comma rule; if a value can contain commas, use the per-key form `data-pagefind-meta="summary:…"` on separate elements.
  - One empty folded element: `<span hidden aria-hidden="true" data-pagefind-index-attrs="data-folded" data-folded={fold(title+' '+summary+' '+tldr.join(' ')+' '+plainText(body))}></span>`. It has no weight attribute.

**`scripts/check-index.mjs` contract** (runs against a started server; `BASE` defaults to `http://localhost:3000`):
- Launch puppeteer, open `${BASE}/vi` and `${BASE}/en`, and in each run `page.evaluate`:
  1. `const pf = await import('/pagefind/pagefind.js'); await pf.init?.();`
  2. `const r = await pf.search(q);`
  3. `return Promise.all(r.results.slice(0, 10).map(x => x.data()))`
- Cases. Each prints PASS/FAIL, and the script exits 1 on any FAIL:
  - vi "du lieu" → some url equals `/vi/posts/discord-cassandra-to-scylladb.html`.
  - vi "dữ liệu" → same.
  - vi "zzqxv" → zero results (negative control).
  - en "messages" → ≥1 result, every url starts with `/en/posts/`.
  - en "dữ liệu" → zero results.
  - Each result's `meta.title` and `meta.summary` are non-empty. For vi results they contain at least one character outside ASCII.

### Task 2: Search client component

**Files:**
- Create: `components/search/load-pagefind.ts`, `components/search/search-box.tsx` (`"use client"`).
- Modify: `dictionaries/{vi,en}.json`.
- Tests: `tests/ui/search-box.test.tsx`.

**Interfaces:**
- `loadPagefind(): Promise<Pagefind | null>`:
  - `import(/* webpackIgnore: true */ '/pagefind/pagefind.js')`, wrapped in try/catch; returns null on failure.
  - Memoized module-wide, and calls `init?.()` once.
  - Local type: `type Pagefind = { init?(): Promise<void>; search(q: string): Promise<{ results: { id: string; data(): Promise<{ url: string; meta: Record<string, string> }> }[] }> }`.
- `SearchBox({ locale, dict }: { locale: Locale; dict: Dictionary })`:
  - **Input:** `<input type="search">` labelled by `dict.search.label`, with placeholder `dict.search.placeholder`. A 200ms debounce, and it searches when `q.trim().length >= 2`.
  - **Results:** up to 10, in `<ol data-search-results>`. Each `<li>` is one row:
    - an `<a href={toSitePath(url)}>` with `meta.title`
    - `<p>` with `meta.summary`
    - mono label with `meta.company`
    - It never renders `excerpt`.
  - **State:** the root has `data-search-state`, one of `idle | loading | results | empty | unavailable | error`. An `aria-live="polite"` region shows `dict.search.searching`, then the count via `plural(locale, n, dict.search.countOne, dict.search.countOther)`, or the message for `empty`, `unavailable` or `error`.
  - **URL:** the query syncs to `?q=` with `history.replaceState`. The `?q=` value is read once on mount.
- Dictionary keys go under a new top-level `search` object in both files, with this exact copy:

| key | vi | en |
|---|---|---|
| title | Tìm kiếm | Search |
| dek | Tìm trong các case study, có dấu hay không dấu đều được. | Search the case studies. |
| label | Từ khóa | Search terms |
| placeholder | Ví dụ: dữ liệu, sự cố, Kafka | e.g. database, outage, Kafka |
| searching | Đang tìm… | Searching… |
| countOne | {n} kết quả | {n} result |
| countOther | {n} kết quả | {n} results |
| empty | Không có bài nào khớp. | No posts match. |
| unavailable | Tìm kiếm chỉ có trên bản build. | Search is available on the built site only. |
| error | Không tải được tìm kiếm. Thử tải lại trang. | Search failed to load. Try reloading the page. |

  - Plus `nav.search`: vi "Tìm kiếm", en "Search", under the existing `nav` object.

Steps:
- [ ] Failing tests, with `loadPagefind` mocked:
  - A fake with two results whose urls are `/vi/posts/a.html` and `/vi/posts/b.html`, and whose meta has accented titles and summaries. After typing "du lieu" and advancing fake timers 200ms:
    - `[data-search-state="results"]`
    - two rows linking to `/vi/posts/a` and `/vi/posts/b`
    - row text equals the meta strings
    - the fake's `excerpt` field (set to `'du lieu <mark>x</mark>'`) does not appear anywhere in the DOM
  - A 1-character query leaves the state `idle` and shows no `ol`.
  - `[]` gives state `empty` and the `empty` text.
  - `loadPagefind` returning null gives `unavailable`.
  - A rejected `search()` gives `error`.
  - Mounting with `location.search = '?q=du%20lieu'` triggers one search.
  - Every vi output string comes from the vi dictionary.
- [ ] Implement. Use the hairline row list classes from the company and topic pages. The input uses the strong hairline, 10px radius, and the global focus ring.
